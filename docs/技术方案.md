## 1. 项目概述

### 1.1 项目背景

为规范公司内部会议室使用，避免时间冲突与资源浪费，开发会议室预约系统。系统支持管理员维护会议室与用户，普通用户可自助查看日程、预约、修改和取消会议室，**无需管理员审批**。

### 1.2 项目目标

- 管理员对会议室进行增删改查
- 管理员对用户进行增删改查，并支持 Excel 批量导入
- 普通用户查看每日 08:00–20:00 日程，了解各会议室占用情况
- 普通用户自助预约、修改、取消会议室（30 分钟粒度，按日展示）
- **根据所选时段智能推荐空闲会议室**；若无空闲则提示修改时间
- 同一会议室同一时段不可重复预约

### 1.3 技术栈

## 5. 核心业务规则

### 5.1 时间规则

| 规则 | 值 | 说明 |
|------|-----|------|
| 可预约时段 | 08:00 – 20:00 | 每日开放时间 |
| 时间粒度 | **30 分钟** | 08:00、08:30、09:00 … 19:30 |
| 日程展示 | **按日** | 选择日期，展示该日所有会议室占用 |
| 网格布局 | **横时间 / 竖会议室** | 横向 08:00–20:00，纵向每行一个会议室 |
| 最短预约 | 30 分钟 | 至少 1 个时间格 |
| 最长预约 | 4 小时 | 可配置 |
| 提前预约上限 | 30 天 | 不可预约超过 30 天后的时段 |
| 历史限制 | 不可预约 | 当天已过去的时段不可选 |

### 5.2 冲突检测

同一会议室、同一日期，新预约时间段 `[start_time, end_time)` 不得与任何 `status = ACTIVE` 的已有预约重叠。

检测逻辑：

```sql
SELECT COUNT(*) FROM booking
WHERE room_id = #{roomId}
  AND booking_date = #{bookingDate}
  AND status = 'ACTIVE'
  AND id != #{excludeId}          -- 修改时排除自身
  AND start_time < #{endTime}
  AND end_time > #{startTime}
```

- 结果 > 0 则冲突，返回 HTTP 409
- 创建和修改预约时均在事务内执行检测

### 5.3 预约流程（无审批）

```
用户选择时段 → 填写表单 → 提交
    → 后端校验（时间范围、权限、冲突）
    → 通过 → 直接写入 status=ACTIVE
    → 失败 → 返回错误信息
```

| 操作 | 规则 |
|------|------|
| 创建 | 校验通过即生效，无需审批 |
| 修改 | 仅预约本人或管理员；重新冲突检测 |
| 取消 | 将 status 改为 `CANCELLED`，保留记录 |

### 5.4 并发控制

高并发下同一时段可能被多人同时提交，采用：

1. 事务内 SELECT … FOR UPDATE 或二次冲突校验
2. 业务层返回明确冲突提示，前端刷新日程并触发推荐

### 5.5 空闲会议室推荐

用户选择**日期 + 开始时间 + 结束时间**后，系统自动计算该时段内无冲突的空闲会议室并推荐，降低选错房间、反复提交失败的操作成本。

#### 5.5.1 触发时机

| 场景 | 行为 |
|------|------|
| 预约 Drawer 打开 | 若已从网格带入日期/时段，立即查询推荐 |
| 修改日期或时段 | 防抖 300ms 后重新查询推荐 |
| 提交冲突（409） | 返回推荐列表，前端展示在表单下方 |
| 从网格点击空白格 | 预填日期/时段，自动查询并展示推荐 |

#### 5.5.2 推荐算法

```
输入：bookingDate, startTime, endTime, excludeBookingId（修改时排除自身）

1. 查询 status=1 且未删除的全部可用会议室
2. 对每个会议室执行冲突检测（同 5.2 逻辑）
3. 无冲突的会议室加入推荐列表
4. 按 capacity 升序、再按 id 升序排序（小会议室优先，可配置）
5. 返回推荐列表；若为空则 available=false
```

查询 SQL 思路：

```sql
SELECT r.*
FROM meeting_room r
WHERE r.status = 1 AND r.deleted = 0
  AND NOT EXISTS (
    SELECT 1 FROM booking b
    WHERE b.room_id = r.id
      AND b.booking_date = #{bookingDate}
      AND b.status = 'ACTIVE'
      AND b.id != #{excludeBookingId}
      AND b.start_time < #{endTime}
      AND b.end_time > #{startTime}
  )
ORDER BY r.capacity ASC, r.id ASC
```

#### 5.5.3 无空闲时的处理

| 情况 | 系统响应 | 前端展示 |
|------|----------|----------|
| 有推荐会议室 | `available: true` + rooms 列表 | 推荐区展示可选会议室，默认选中第一个 |
| 无推荐会议室 | `available: false` | 提示：**「暂时没有空闲会议室，请修改其他时间」** |
| 无推荐 | — | 「确认预约」按钮禁用，引导用户调整日期或时段 |

#### 5.5.4 交互流程

```
用户选择日期 2026-07-08、时段 09:00-10:30
    → 前端调用 GET /api/rooms/recommend
    → 后端返回 [302会议室, 401会议室]
    → 前端展示推荐列表，用户选择或确认默认项
    → 填写主题 → 提交预约

若返回 available=false
    → 展示「暂时没有空闲会议室，请修改其他时间」
    → 用户修改时段后重新触发推荐
```

#### 5.5.5 服务设计

```java
RoomRecommendService
├── recommend(date, startTime, endTime, excludeBookingId?)
│     → 返回 RecommendResult { available, rooms[], message }
└── 复用 ConflictChecker 逻辑，避免与预约模块不一致
```

## 8. 用户管理与批量导入

### 8.1 手动管理

管理员在用户管理页面可：

| 操作 | 说明 |
|------|------|
| 新增 | 填写用户名、初始密码、姓名、角色 |
| 编辑 | 修改姓名、角色、启用/禁用状态 |
| 重置密码 | 设为默认密码（如 `123456`），用户首次登录后可自行修改 |
| 删除 | 逻辑删除，已删除用户不可登录 |

**约束：**

- 用户名唯一，不可重复
- 至少保留 1 个管理员账号，不可删除最后一个管理员
- 禁用用户不可登录，但不影响其历史预约记录展示

### 8.2 Excel 批量导入

#### 8.2.1 导入模板

管理员点击「下载模板」获取标准 Excel 文件：

| 列 | 字段 | 必填 | 说明 |
|----|------|:----:|------|
| A | 用户名 | ✅ | 登录账号，唯一 |
| B | 姓名 | ✅ | 真实姓名 |
| C | 角色 | ✅ | 填 `USER` 或 `ADMIN` |
| D | 初始密码 | | 为空则默认 `123456` |

模板示例：

| 用户名 | 姓名 | 角色 | 初始密码 |
|--------|------|------|----------|
| zhangsan | 张三 | USER | |
| lisi | 李四 | USER | abc123 |
| wangwu | 王五 | ADMIN | |

#### 8.2.2 导入流程

```
管理员上传 Excel
    → 后端解析文件（Apache POI）
    → 逐行校验（必填、格式、用户名唯一）
    → 校验通过的行批量 INSERT
    → 返回导入结果（成功数、失败数、失败明细）
    → 前端展示结果表格
```

#### 8.2.3 校验规则

| 规则 | 错误提示 |
|------|----------|
| 文件格式 | 仅支持 .xlsx / .xls |
| 文件大小 | 不超过 5MB |
| 单次行数 | 不超过 500 行 |
| 用户名空 | 「用户名不能为空」 |
| 用户名重复（文件内） | 「文件中用户名重复」 |
| 用户名重复（数据库） | 「用户名已存在」 |
| 姓名空 | 「姓名不能为空」 |
| 角色非法 | 「角色只能为 USER 或 ADMIN」 |
| 密码长度 | 6–20 位 |

#### 8.2.4 导入策略

- **部分成功模式**：合法行正常导入，非法行跳过并记录错误
- 不做事务全回滚，避免一条错误导致全部失败
- 导入完成后展示结果摘要与失败明细，支持导出失败记录

#### 8.2.5 后端实现

```java
// UserImportService
public ImportResult importUsers(MultipartFile file) {
    List<UserImportRow> rows = ExcelParser.parse(file);
    ImportResult result = new ImportResult();
    for (int i = 0; i < rows.size(); i++) {
        UserImportRow row = rows.get(i);
        String error = validate(row);
        if (error != null) {
            result.addError(i + 2, row.getUsername(), error); // +2 对应 Excel 行号
            continue;
        }
        userService.createUser(row.toUser());
        result.incrementSuccess();
    }
    return result;
}
```

#### 8.2.6 前端交互

1. 用户管理页顶部：「下载模板」+「批量导入」按钮
2. 点击「批量导入」→ Upload 组件选择文件 → 上传
3. 导入完成后 Modal 展示：
   - 总计 / 成功 / 失败 数量
   - 失败明细表格（行号、用户名、原因）
4. 关闭后自动刷新用户列表
